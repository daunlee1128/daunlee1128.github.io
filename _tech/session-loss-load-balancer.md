같은 사용자를 같은 서버에 고정해 로그인은 유지했지만, 세션을 서버 안에 두는 전제는 그대로 남았다.
분산 방식을 hash 기반으로 바꿔 같은 사용자의 요청을 한 서버로 모았다.
세션 저장 위치와 분산 규칙을 한 쌍으로 보는 기준, 그 고정이 언제 다시 깨지는지를 얻는다.
서버 여러 대를 로드밸런서 뒤에 두고 세션은 각 서버 안에 둔 채 운영하는 사람을 위한 글이다.
답은 [분산 방식을 바꾼 절](#fix)에 있다.

{: #root-cause data-k="ROOT CAUSE"}
## 분산 정책과 세션 저장 위치가 서로를 몰랐다

사용자가 두 서버를 번갈아 접속하면서 세션이 공유되지 않아 재로그인이 반복됐다.

통합회원 세션은 회원플랫폼이 따로 관리했다. 이 서비스는 그 세션이 발급한 쿠키를 받아,
서비스 자체의 보안 세션을 새로 관리하는 중이었다. 그 신규 세션을 서버 로컬에 저장했다.

로드밸런서는 요청마다 부하가 적은 서버로 보냈다. 세션 저장 위치와 이 분산 규칙은 각각 정해졌다.
그래서 다음 요청이 닿은 서버에는 그 사용자의 세션이 없었다.

{: #fix data-k="FIX"}
## 같은 사용자가 같은 서버에 붙도록 분산을 hash 기반으로 바꿨다

이 글의 조건: 세션을 각 서버 안에 두고, 서버 여러 대를 로드밸런서 뒤에 둔 구성.

같은 사용자의 요청은 같은 서버로 간다.
그 서버에 세션이 있으니 재로그인도 멈춘다.

같은 증상이면 세션 저장 위치와 요청 분산 규칙을 나란히 놓고 본다.

{: #prevention data-k="PREVENTION"}
## 세션을 밖으로 빼기 전까지는 전제가 그대로 남는다

이 처방은 세션을 서버 로컬에 두는 전제를 유지한다. 서버를 넣거나 빼면 다시 흔들린다.

서버를 그룹에 넣거나 빼면 키 대부분이 다른 서버로 다시 매핑될 수 있다(nginx [`hash`][hash] 지시어 문서, 2026-09-14 확인).
재매핑을 줄이는 방식을 쓰더라도 옮겨진 사용자의 세션은 새 서버에 없다.

근본 해법은 세션을 서버 밖으로 빼는 것이다.

[hash]: https://nginx.org/en/docs/http/ngx_http_upstream_module.html#hash
